<task type="auto">
  <name>Task 2: Build Student Micro-Pass Billing & Viral Referral Engine APIs</name>
  <files>server/routes/billing.py, server/routes/referral.py, server/routes/auth.py</files>
  <action>
    1. In `server/routes/billing.py`:
       - Define student plans catalog:
         - `sprint_pass`: ₹199 (19900 paise), 14 days duration.
         - `placement_season`: ₹499 (49900 paise), 90 days duration.
       - Add request model: `CreateOrderRequest(plan_id: str = "sprint_pass")`.
       - Update `POST /api/billing/order`:
         - Validates `plan_id` in `["sprint_pass", "placement_season", "pro"]`.
         - Calculates amount in paise (19900 or 49900).
         - Sets order notes `{ organization_id, user_id, plan_id }`.
       - Update `POST /api/billing/verify`:
         - Extracts `plan_id` from order notes or verify payload.
         - Sets `sub.plan = plan_id.upper()` (`SPRINT_PASS` or `PLACEMENT_SEASON`).
         - Calculates `current_period_end`:
           - `sprint_pass`: `now + timedelta(days=14)`. If existing pass is still active, add 14 days to `current_period_end`.
           - `placement_season`: `now + timedelta(days=90)`. If existing pass is active, add 90 days.
         - Saves `Payment(amount=amount, ...)`.
       - Update `POST /api/billing/mock-upgrade`:
         - Accepts `plan_id: str = "sprint_pass"` and grants the corresponding pass duration.
       - Add `GET /api/billing/plans`:
         - Returns available student plans, prices, durations, features list, and current user's active pass details.
    2. Create `server/routes/referral.py` (`referral_router = APIRouter(prefix="/api/referrals", tags=["referrals"])`):
       - `GET /api/referrals/me`:
         - Requires authenticated user.
         - Returns user's `referral_code`, `share_url` (`https://resumatch.io/?ref={code}`), total `referred_count`, `unlocked_days`, and progress towards next reward (`referred_count % 3`).
       - Helper `process_referral_reward(referrer_id: str, db: Session)`:
         - Counts unrewarded referrals for referrer.
         - If count >= 3:
           - Mark batch of 3 referrals as `reward_granted = True`.
           - Look up referrer's primary organization subscription.
           - If `sub.current_period_end and sub.current_period_end > now`:
             `sub.current_period_end += timedelta(days=7)`
           - Else:
             `sub.plan = "SPRINT_PASS"`, `sub.status = "active"`, `sub.current_period_start = now`, `sub.current_period_end = now + timedelta(days=7)`
           - Commit reward.
    3. In `server/routes/auth.py`:
       - On `POST /api/auth/register`:
         - Generate a 7-character random uppercase alphanumeric `referral_code` for the new user (e.g. `STU8492`).
         - If optional `referred_by_code` is passed in registration request:
           - Look up referrer by `referral_code`.
           - If found and not self:
             - Create `Referral(referrer_user_id=referrer.id, referred_user_id=new_user.id)`.
             - Call `process_referral_reward(referrer.id, db)`.
    4. Register `referral_router` in `server/app.py`.
  </action>

| User Registration → Referral Credit | Self-referrals or duplicate referral abuse |

## STRIDE Threat Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-10-01 | Tampering | Razorpay Order Price | high | mitigate | Hardcode prices on server by `plan_id` in paise; never accept client-supplied amount |
| T-10-02 | Elevation of Privilege | Self-Referral Exploits | high | mitigate | Check `referrer_user_id != referred_user_id`, enforce unique constraint on `referred_user_id` so one student can only be referred once |
| T-10-03 | Denial of Service / Abuse | Mock Upgrade in Production | high | mitigate | Strictly block `mock-upgrade` if `ENVIRONMENT == "production"` |
</threat_model>
