<objective>
Harden the ResuMatch API backend for high-concurrency production deployments by offloading heavy ML inference and document parsing from the ASGI event loop using Starlette's `run_in_threadpool`, implementing a distributed Redis embedding cache with in-memory fallback, and replacing dead Flask limiter code with active `slowapi` FastAPI rate limiting.

Purpose: CPU-bound PyTorch/ONNX matrix multiplications block the single-threaded asyncio event loop in FastAPI, causing concurrent HTTP requests to hang. Additionally, in-memory embedding caches and missing rate limiting limit scalability across multi-worker deployments.
Output: Non-blocking async endpoints, Redis-backed embedding cache, active FastAPI rate limiter, and performance test suite.
</objective>

  <action>
    In `server/services/ai_engine.py`:
    1. Implement `RedisEmbeddingCache`:
       - Reads `REDIS_URL` from environment (`os.environ.get("REDIS_URL")`).
       - If `REDIS_URL` is set, initializes `redis.from_url(REDIS_URL, decode_responses=False, socket_timeout=2.0)`.
       - Computes cache key: `f"emb:{hashlib.sha256(text.encode('utf-8')).hexdigest()}"`.
       - `get(text)`: Attempts to fetch bytes from Redis; if found, deserializes to numpy array using `np.frombuffer(raw, dtype=np.float32)`.
       - `set(text, embedding_np, ttl=86400)`: Stores raw bytes `embedding_np.astype(np.float32).tobytes()` with 24-hour expiration.
       - Any Redis connection error or timeout gracefully falls back to `_embedding_cache` (the existing bounded LRU cache) with `logger.warning`.
    2. Integrate `RedisEmbeddingCache` into `get_cached_embedding(text)`:
       - Checks Redis cache first (if available), then local LRU cache, then computes embedding via PyTorch/ONNX and saves to both.
  </action>

         from slowapi import Limiter

         redis_url = os.environ.get("REDIS_URL")
         storage_uri = redis_url if redis_url else "memory://"
