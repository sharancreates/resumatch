<objective>
Update database models and Alembic migrations for Razorpay billing integration, implement Razorpay order creation (`/api/billing/order`), and implement cryptographic payment signature verification (`/api/billing/verify`) with RBAC guardrails.

Purpose: The user requires Razorpay instead of Stripe for billing. The database schema currently assumes Stripe-only customer IDs, lacks the `Payment` model in SQLAlchemy, and has no Razorpay order creation or verification endpoints.
Output: Razorpay-ready `models.py` and `schema.prisma`, forward Alembic migration, and order/verify endpoints with HMAC SHA-256 validation.

  <name>Task 3: Implement Razorpay order creation and signature verification</name>
  <files>server/routes/billing.py</files>
  <action>
    In `server/routes/billing.py`:
    1. Initialize Razorpay credentials:
       - Read `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET`.
    2. Implement `POST /api/billing/order`:
       - Authenticated via `get_current_user`.
       - RBAC guard: caller must be `OWNER` or `ADMIN` in their active organization (`403 Forbidden` on VIEWER/RECRUITER).
       - Create order via Razorpay API (or direct HTTPS request via `requests` to `https://api.razorpay.com/v1/orders` with HTTP Basic Auth).
       - Amount: 49900 paise (₹499) for PRO monthly tier.
       - Pass `notes: {"organization_id": org_id, "user_id": user.id}`.
       - Returns `{"status": "success", "order_id": order["id"], "amount": order["amount"], "currency": order["currency"], "key_id": key_id}`.
       - Fallback to mock order if credentials not configured.
    3. Implement `POST /api/billing/verify`:
       - Request body: `razorpay_order_id`, `razorpay_payment_id`, `razorpay_signature`.
       - Verifies HMAC SHA-256: `hmac.new(secret.encode(), f"{order_id}|{payment_id}".encode(), hashlib.sha256).hexdigest() == signature`.
       - On valid signature:
         - Upgrades `Subscription` to `plan="PRO"`, `status="active"`, `current_period_end = now + 30 days`.
         - Inserts `Payment(id=uuid, organization_id=org_id, razorpay_payment_id=payment_id, razorpay_order_id=order_id, amount=49900, status="captured")`.
         - Inserts `AuditLog(action="UPGRADE_SUBSCRIPTION", target_type="SUBSCRIPTION")`.
         - Commits and returns `{"status": "success", "message": "Subscription upgraded to PRO successfully!"}`.
    4. Keep `POST /api/billing/checkout-session` as backward-compatible alias delegating to order creation.
  </action>

<threat_model>
## Trust Boundaries
| Boundary | Description |
|---|---|
| Client Payment Response → Backend | Client supplies payment ID and signature; server must cryptographically verify HMAC |
| Billing Route → Database | Only organization owners/admins can trigger billing transactions |

## STRIDE Threat Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-04-01 | Tampering | `POST /api/billing/verify` | critical | mitigate | Cryptographically verify HMAC SHA-256 signature using RAZORPAY_KEY_SECRET; reject invalid signatures with 400 |
| T-04-02 | Elevation of Privilege | `POST /api/billing/order` | high | mitigate | Require user to have OWNER or ADMIN role in active organization before creating orders |
| T-04-03 | Replay Attacks | Payment verification | high | mitigate | Ensure payment_id is checked against existing Payment records to prevent duplicate activations |
</threat_model>
