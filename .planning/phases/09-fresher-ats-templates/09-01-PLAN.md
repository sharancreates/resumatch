Purpose: Students need their tailored resumes formatted into clean, recruiter-approved documents that pass Indian campus placement cell rules and multinational ATS parsers.
Output: Production template engine, streaming export endpoints, and automated pytest suite.

<task type="tracer">
  <name>Task 1: Build the Resume Template Engine with PDF and DOCX pipelines</name>
  <files>server/services/resume_templates.py</files>
  <action>
    Create `server/services/resume_templates.py`:
    1. **Template Definitions**:
       - `classic_tech`: High-density SWE layout prioritizing skills & projects with tech tags.
       - `modern_minimal`: Clean sans-serif layout with subtle dividers for product & frontend roles.
       - `data_analytics`: Quantitative layout highlighting tools (Python, SQL, Tableau) & metrics.
       - `campus_placement`: Strict institutional Indian engineering format (Education with CGPA first, Projects, Skills, Coursework).
    2. **Structured Resume Normalizer (`normalize_resume_data`)**:
       - Parses raw resume text or structured JSON into a clean dictionary:
         - `candidate_name`: Extracted from header (or fallback "Candidate").
         - `contact`: `email`, `phone`, `linkedin`, `github`.
         - `education`: Degree, institution, year, CGPA.
         - `skills`: Grouped skills or list.
         - `projects`: List of `{title, stack, bullets}`.
         - `coursework`: List of CS core subjects.
         - `certifications`: List of credentials.
    3. **ReportLab PDF Generator (`generate_resume_pdf`)**:
       - Letter/A4 format with tight, balanced margins (36pt / 0.5 in).
       - Uses `SimpleDocTemplate`, `Paragraph`, `Spacer`, and clean lines.
       - Configures typography per template (font sizes 9-11pt body, 12-14pt headers, 18-22pt title) budgeted to fit 1 page.
       - Returns `bytes` starting with `%PDF-`.
    4. **python-docx Generator (`generate_resume_docx`)**:
       - Standard Word margins (0.75 in).
       - Applies native Word Heading 1 / 2 styles and `List Bullet` styles.
       - Never inserts text boxes or multi-column nested tables.
       - Returns `bytes` starting with PK zip magic bytes (`PK\x03\x04`).
  </action>
  <verify>
    <automated>python -m py_compile server/services/resume_templates.py</automated>
  </verify>
  <done>Template engine renders 4 templates in both PDF and DOCX formats.</done>
</task>

  <name>Task 2: Wire Resume Export and Template Listing Endpoints in analyze router</name>
  <files>server/routes/analyze.py</files>
  <action>
    In `server/routes/analyze.py`:
    1. Define request model:
       - `ExportResumeRequest`:
         - `template_id: str = "classic_tech"`
         - `format: str = "pdf"` (or `"docx"`)
         - `resume_text: str | None = None`
         - `analysis_id: str | None = None`
         - `resume_version_id: str | None = None`
    2. Implement `GET /api/resume/templates`:
       - Returns metadata for the 4 templates (id, name, description, recommended_for, preview_tag).
    3. Implement `POST /api/resume/export`:
       - Resolves resume text from `resume_text`, `resume_version_id`, or `analysis_id`.
       - Normalizes structured resume data.
       - Offloads generation to threadpool:
         - If `format == "docx"`: `await run_in_threadpool(generate_resume_docx, resume_data, template_id)`
         - If `format == "pdf"`: `await run_in_threadpool(generate_resume_pdf, resume_data, template_id)`
       - Returns `Response` with media type:
         - PDF: `application/pdf`
         - DOCX: `application/vnd.openxmlformats-officedocument.wordprocessingml.document`
       - Sets `Content-Disposition: attachment; filename="{candidate_name}_Resume_{template_id}.{format}"`.
  </action>
