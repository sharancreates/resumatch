<objective>
Integrate cloud object storage (AWS S3 / Cloudflare R2 with local fallback) into resume upload pipelines, replace the "database-direct" file_url placeholder with real storage links, and implement secure authenticated download endpoints with presigned URL support.

Purpose: Resumes currently have no persistent document storage; resume text is stored in the database but raw uploaded files are discarded with `file_url="database-direct"`.
Output: Connected storage upload in `analyze.py`, presigned URL generator in `storage.py`, authenticated download endpoints, and comprehensive tests.
</objective>

<task type="tracer">
  <name>Task 1: Enhance server/utils/storage.py with presigned URLs and deletion</name>
  <files>server/utils/storage.py</files>
  <action>
    In `server/utils/storage.py`:
    1. Implement `generate_presigned_url(file_url: str, expiration: int = 3600) -> str`:
       - If S3 client and bucket are configured, extract object key from `file_url` and call `s3_client.generate_presigned_url('get_object', Params={'Bucket': bucket_name, 'Key': key}, ExpiresIn=expiration)`.
       - If `file_url` is local (`/api/uploads/...`), return `file_url` directly.
    2. Implement `delete_file(file_url: str) -> bool`:
       - Delete from S3 if configured, or remove from `LOCAL_UPLOAD_DIR` if local file exists.
    3. Implement `is_cloud_storage_configured() -> bool`:
       - Return `True` if AWS credentials and bucket name are set, else `False`.
  </action>
  <verify>
    <automated>python -m py_compile server/utils/storage.py</automated>
  </verify>
  <done>storage.py provides presigned URL generation, file deletion, and cloud status inspection.</done>
</task>

<task type="auto">
  <name>Task 2: Connect storage uploads and add download endpoints in server/routes/analyze.py</name>
  <files>server/routes/analyze.py</files>
  <action>
    In `server/routes/analyze.py`:
    1. In `parse_pdf_endpoint`:
       - When file is uploaded and parsed successfully, call `upload_file(content, file.filename, file.content_type or 'application/octet-stream')`.
       - Return `{"status": "success", "text": text, "file_url": file_url}`.
    2. In `analyze_endpoint`:
       - Accept optional `file_url: str | None = None` in `AnalyzeRequest`.
       - When creating `ResumeVersion`, set `file_url=req.file_url or "database-direct"`.
    3. Add dedicated resume upload endpoint `POST /api/resumes/upload`:
       - Accepts `file: UploadFile = File(...)`, optional `title: str = Form("Uploaded Resume")`.
       - Validates magic bytes (`%PDF-`, `PK\x03\x04`).
       - Extracts text and structure.
       - Uploads file via `upload_file`.
       - Creates/updates `Resume` and appends `ResumeVersion` with real `file_url`.
       - Returns resume and version details.
    4. Add authenticated download endpoint `GET /api/resumes/{resume_id}/versions/{version_id}/download`:
       - Validates that user is owner or an organization member.
       - If S3 presigned URL is generated, redirect (307) or stream file bytes.
       - If local file, stream with proper `Content-Disposition`.
    5. Add local file streaming endpoint `GET /api/uploads/{filename}`:
       - Safely prevents directory traversal (validates filename has no path separators).
       - Streams file from `LOCAL_UPLOAD_DIR` with correct MIME type.
  </action>
  <verify>
    <automated>python -m py_compile server/routes/analyze.py</automated>
  </verify>
  <done>Raw resume documents are stored in object storage and downloadable via authenticated endpoints.</done>

| File Download → Client | Download endpoints must authenticate caller and enforce tenant ownership |

## STRIDE Threat Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03-01 | Tampering | `server/utils/storage.py` | high | mitigate | Generate UUID-prefixed unique filenames; never use raw user filenames as storage keys |
| T-03-02 | Information Disclosure | `GET /api/uploads/{filename}` | high | mitigate | Sanitize filename against `..` directory traversal and verify file exists strictly inside `LOCAL_UPLOAD_DIR` |
